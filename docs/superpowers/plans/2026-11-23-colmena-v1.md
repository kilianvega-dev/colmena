# Colmena v1: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objetivo:** un panel local en el navegador con varias sesiones de Claude Code y terminales en paneles, que muestra el estado de cada sesión y avisa cuando una espera a Kilian.

**Arquitectura:** un servidor Node (TypeScript que se ejecuta directo con Node 24) mantiene las terminales con `node-pty` y habla con la interfaz por WebSocket. Claude se lanza con `--settings` apuntando a un archivo de hooks de Colmena. Los hooks ejecutan un script que manda el evento al servidor por HTTP local. La interfaz es React y se sirve compilada desde el mismo servidor.

**Stack:** Node 24.22 (type stripping nativo, sin `tsx`), `ws`, `node-pty`, React 19, Vite 7, Tailwind 4 (`@tailwindcss/vite`), `@xterm/xterm` + `@xterm/addon-fit`, `react-resizable-panels`, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-23-colmena-design.md`

## Restricciones globales

- Windows 11. Node 24.22.1. Claude Code 2.1.323 (`claude.exe` en el PATH).
- El servidor escucha solo en `127.0.0.1`. Puerto por defecto `4777`, cambiable con la variable de entorno `COLMENA_PORT`.
- Nunca se escribe en `~/.claude/settings.json`. Los hooks solo entran por `--settings`.
- Comando de sesión nueva: `claude --session-id <uuid> --settings <hooksPath>`. Comando para reanudar: `claude --resume <uuid> --settings <hooksPath>`.
- Estados exactos: `iniciando`, `trabajando`, `esperando`, `terminado`, `cerrado`.
- Datos locales en `%APPDATA%\colmena\` (`state.json` y `hooks.json`).
- TypeScript ejecutable por Node: los imports llevan la extensión `.ts`, y no se usan `enum`, `namespace` ni parameter properties (`erasableSyntaxOnly`).
- Repo público `kilianvega-dev/colmena`. Un commit por tarea como mínimo, con mensajes en español.
- Textos de la interfaz en español.

## Foco de revisión

1. **Carpeta con espacios o acentos** (`C:\Users\User\OneDrive\Desktop\Proyectos\Portafolio Kilian`): la sesión debe abrir ahí. Si la carpeta no existe, se avisa con un error claro y no se lanza ningún proceso. Prueba en la Tarea 6.
2. **Evento de hook con JSON roto, sin token o con un `session_id` desconocido:** responde 400/401/404, no cambia ningún estado y el servidor sigue vivo. Prueba en la Tarea 7.
3. **`state.json` corrupto o ausente:** Colmena arranca vacía y guarda el archivo corrupto como `state.json.bak`. Prueba en la Tarea 5.
4. **`claude.exe` que no existe o sale de inmediato:** el panel pasa a `cerrado` con el código de salida y no queda colgado en `iniciando`. Prueba en la Tarea 6.
5. **Dos pestañas abiertas a la vez:** las dos reciben el mismo estado y la misma salida, y escribir en una se ve en la otra. Prueba en la Tarea 7.

## Tipos compartidos (`server/protocol.ts`, se crea en la Tarea 2)

```ts
export type SessionKind = 'claude' | 'terminal';
export type SessionStatus = 'iniciando' | 'trabajando' | 'esperando' | 'terminado' | 'cerrado';
export interface SessionInfo { id: string; kind: SessionKind; cwd: string; status: SessionStatus; exitCode: number | null; }

export type ClientMessage =
  | { type: 'create'; kind: SessionKind; cwd: string }
  | { type: 'resume'; id: string }
  | { type: 'close'; id: string }      // mata el proceso, conserva el panel
  | { type: 'remove'; id: string }     // quita el panel (mata si vive)
  | { type: 'input'; id: string; data: string }
  | { type: 'resize'; id: string; cols: number; rows: number }
  | { type: 'reorder'; ids: string[] };

export type ServerMessage =
  | { type: 'snapshot'; sessions: SessionInfo[]; order: string[]; recents: string[] }
  | { type: 'session'; session: SessionInfo }
  | { type: 'output'; id: string; data: string }
  | { type: 'replay'; id: string; data: string }
  | { type: 'removed'; id: string }
  | { type: 'error'; message: string };
```

### Task 6: SessionManager

**Archivos:**
- Crear: `server/ring-buffer.ts`, `server/sessions.ts`
- Prueba: `tests/ring-buffer.test.ts`, `tests/sessions.test.ts`

**Interfaces:**
- Consume: `nextStatus` (Tarea 2), `SessionInfo` y `SessionKind` (Tarea 2).
- Produce:
  - `class RingBuffer { constructor(maxBytes: number); push(s: string): void; toString(): string }`. Si se pasa del límite, descarta lo más antiguo. Límite usado: `200_000`.
  - `type Spawn = (file: string, args: string[], opts: { cwd: string; env: Record<string,string>; cols: number; rows: number }) => PtyLike`
  - `interface PtyLike { onData(cb:(d:string)=>void): void; onExit(cb:(e:{exitCode:number})=>void): void; write(d:string): void; resize(c:number,r:number): void; kill(): void }`
  - `class SessionManager extends EventEmitter` con eventos `'session'(SessionInfo)`, `'output'(id, data)` y `'removed'(id)`.
    - `constructor(opts: { spawn: Spawn; hooksPath: string; port: number; token: string; claudeBin: string; shell: string })`
    - `create(kind: SessionKind, cwd: string): SessionInfo`: lanza el error `Error('La carpeta no existe: <cwd>')` si `cwd` no existe o no es carpeta, y en ese caso no llama a `spawn`.
    - `resume(id: string): SessionInfo`: solo para `claude` en estado `cerrado`. Vuelve a `iniciando`.
    - `restore(saved: SavedState['sessions']): void`: registra las sesiones guardadas como `cerrado` sin lanzar nada.
    - `applyHook(sessionId: string, event: string): boolean`: devuelve `false` si el id no existe.
    - `write(id, data)`, `resize(id, cols, rows)`, `close(id)`, `remove(id)`, `killAll()`
    - `list(): SessionInfo[]`, `replay(id): string`
- Lanzamiento: si `kind` es `claude`, `spawn(claudeBin, ['--session-id', id, '--settings', hooksPath], …)` (o `['--resume', id, '--settings', hooksPath]` al reanudar). Si es `terminal`, `spawn(shell, [], …)`. El env es `process.env` más `COLMENA_PORT`, `COLMENA_TOKEN` y `COLMENA_SESSION=id`. Tamaño inicial 120x30. Cuando el proceso sale, la sesión pasa a `cerrado` con `exitCode`. El id es `crypto.randomUUID()`. Valores por defecto en `index.ts`: `claudeBin = 'claude.exe'`, `shell = 'powershell.exe'`.

### Task 7: servidor HTTP y WebSocket

**Archivos:**
- Crear: `server/server.ts`, `server/index.ts`
- Prueba: `tests/server.test.ts`

**Interfaces:**
- Consume: todo lo anterior.
- Produce: `createServer(opts: { manager: SessionManager; port: number; token: string; staticDir: string | null; devPort?: number; stateFile: string; recents: string[] }): Promise<{ close(): Promise<void>; port: number }>`
- Comportamiento:
  - Escucha en `127.0.0.1`. Toda petición HTTP con `Host` no permitido recibe 403.
  - `POST /hook`: el token del header debe coincidir (si no, 401). Cuerpo de máximo 64 KB, parseado con `parseHookPayload` (si es `null`, 400). Llama a `manager.applyHook` (si devuelve `false`, 404). Si todo va bien, 204.
  - `GET /*`: sirve `staticDir` (con `index.html` como respaldo). Si `staticDir` es `null`, responde 404.
  - WebSocket en `/ws`: rechaza el upgrade si `Host` u `Origin` no están permitidos. Al conectar manda un `snapshot` y un `replay` por cada sesión. Reenvía a **todos** los clientes los eventos `session`, `output` y `removed`. Ejecuta los `ClientMessage`. Si `create` falla, responde `{type:'error', message}` solo a ese cliente. Un mensaje que no se puede parsear se ignora.
  - Un `create` que sale bien agrega su `cwd` a las carpetas recientes con `addRecent` y manda un `snapshot` nuevo a todos los clientes.
  - Cada vez que cambian las sesiones, el orden o las carpetas recientes, se guarda el estado con `saveState`, con un debounce de 300 ms.
- `index.ts`: dataDir = `%APPDATA%\colmena`. Escribe los hooks, carga el estado, crea el manager con el `spawn` real de `node-pty` y llama a `restore`. Crea el token con `crypto.randomBytes(24).toString('hex')`. `staticDir = dist/` si existe. En `SIGINT` y `SIGTERM`: `killAll`, guardar y salir. Imprime `Colmena en http://127.0.0.1:<port>`.

- [ ] **Paso 1: pruebas que fallan** (servidor real en el puerto 0, manager con el spawn falso de la Tarea 6, clientes `ws`):
  - **Foco 2:** `POST /hook` sin token da 401, con JSON roto da 400, con un id desconocido da 404, y con un id válido y `Stop` da 204 y el estado cambia a `terminado`. Después de las peticiones con error el servidor sigue respondiendo.
  - Un WebSocket con `Origin: https://evil.com` es rechazado. `GET /` con `Host: evil.com` da 403.
  - Al conectar, el primer mensaje es `snapshot`.
  - **Foco 5:** dos clientes conectados. El cliente A manda `create`, y los dos reciben `session`. La salida del proceso (`emitData('hola')`) llega a los dos. El cliente B manda `input`, y el pty falso recibe ese texto.
  - `create` con una carpeta inexistente: solo ese cliente recibe `error`.
- [ ] **Paso 2 a 4:** que fallen, implementar, que pasen.
- [ ] **Paso 5:** prueba manual: `node server/index.ts` y luego, desde otra terminal, `curl -i http://127.0.0.1:4777/` da 404 (todavía no hay interfaz) y `curl -i -H "Host: evil.com" http://127.0.0.1:4777/` da 403.
